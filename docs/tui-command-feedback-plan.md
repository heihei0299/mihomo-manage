# TUI 命令执行反馈

> 状态：已实现；相关 TUI 自动回归和模拟 PTY 交互验证通过。根包回归存在一项已确认的既有失败，见下文。

## 已确认的需求

- 用户选择并执行具体命令后，TUI 应明确反馈该命令的执行结果，不能只表现为画面闪动。
- 成功和失败都必须有明确反馈，以用户提出的 `reload` 为首个回归场景。
- 结果带有具体命令名称；失败摘要包含原因，完整错误保留在可滚动正文。
- 主界面的结果区保留最近一次执行结果，直到下一次执行命令才替换；不自动消失，也不要求额外按键关闭。
- 状态刷新、滚动及进入子页面后返回不会清除结果；状态查询失败时，查询错误与命令执行结果分别保留。
- 本轮关注命令执行反馈，不据此扩展为整体导航或布局重设计。

## 实现范围与验证边界

- 复用已有结果状态和固定提示区，统一服务控制、安装／升级／卸载、自动启动、定时设置及订阅来源编辑的结果名称。
- 不改变命令的业务执行、CLI、配置格式、原有导航和按键；不添加人为延时或弹窗。
- 自动回归使用模拟服务，覆盖成功、失败、结果保留及下一次命令替换，不触发真实服务变更。
- 回归已在修改前稳定失败，明确捕获通用文案缺少命令名、进入配置页清除结果和状态查询失败遮盖结果。这不等同于已查明真实终端闪烁的根因。

## 反馈示例

```text
✓ Reload succeeded
✗ Reload failed: <具体原因>
```
